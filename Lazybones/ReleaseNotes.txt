v.1.4.4
   - Fix: the new day's timer could start counting while you were still away. The 1.4.3 fix promised the clock would wait at a locked screen, but it only recognized "away" for modes that pause when you step away — by default that's standing, not sitting. So when the day rolled over while you were gone and the new day began seated (the default), the timer resumed at the rollover and counted down unattended until you arrived, eating the first part of the day and sometimes firing the first stand reminder before you'd even sat down. The rollover now reads the actual screen-lock state instead, so the fresh cycle waits paused at a locked screen regardless of mode and starts only when you unlock.

v.1.4.3
   - Fix: "Open at login" could silently stop working even while the setting showed as on. The saved preference and the actual OS entry (the Windows registry Run key / the macOS LaunchAgent) were only ever synced at the moment you toggled the checkbox, so if the entry was lost — most often because it had been written under the app's previous name and didn't survive the rename — nothing ever re-created it. The preference is now re-applied to the OS on every launch, so a setting that says "on" actually starts the app at login, and the entry is rewritten with the current install path.
   - Uninstalling now removes the launch-at-login entry on Windows, instead of leaving behind a Run-key value pointing at the deleted app.
   - Fix: the timer could come up paused on the first launch of a new day — most noticeably when you'd left for the day and reopened the app the next morning. A day rollover applied while the timer was paused (for example, paused by a screen lock when you last closed the app, or because you'd dismissed the change-position prompt) reset the mode but never resumed the clock, and on a fresh launch nothing else restarted it. A rollover now always starts the new day's cycle running, the same as one that fires while the timer is already going — except when you're actively away at a locked screen, where it stays paused until you return. (Dismissing the prompt still stops the clock on purpose — only a day rollover revives it.) This extends the 1.4.1/1.4.2 rollover fixes, which only covered the case where the change-position prompt was open.
   - Internal: added a small diagnostic log (diagnostics.log, next to the saved state) recording app start/exit and every day-rollover decision, to track down a rollover that fired at a time the logic says is impossible.

v.1.4.2
   - Fix: regression from 1.4.1 — when the day rolled over while the change-position prompt was open, the new day's timer started paused instead of running. A rollover now keeps the timer running across the boundary, the same as a rollover that fires during an active cycle.

v.1.4.1
   - Fix: if the day rolled over while the change-position prompt was open — e.g. a cycle finished while you were away and you returned after the new day began — the finished cycle was logged as a rollover reset and lost its credit, and the stale prompt stayed up. The completed cycle now counts toward your day and streak, and the prompt is dismissed automatically when the rollover fires.

v.1.3.0

Locking your screen or stepping away pauses the timer based on the mode you're in — standing pauses by default (time away isn't standing at your desk, so the cycle shouldn't complete while you're gone), while sitting keeps counting by default (time away from your chair is time not sitting, so it brings your next stand reminder closer). Both are in Settings.

v.1.2.1
   - Fix: the localized interface was broken in the 1.2.0 release build — the dashboard tabs showed an internal code name instead of their labels, and changing the language didn't take effect until the window was reopened. The 1.2.0 language work routed labels through a reflection-based binding that the release build's trimming stripped out. v.1.1.1
   - Fix: auto-update restarts no longer drop the in-flight cycle. Velopack's default ApplyUpdatesAndRestart bypassed Avalonia's window-close events, so MainWindowViewModel.Dispose never ran and the cycle's state was silently lost (visible as missing standing cycles in your history after an update). The app now uses WaitExitThenApplyUpdates + a graceful Avalonia shutdown so cycle state survives the patch.
   - Streak math reworked: a "streak" is now one full daily-goal completion, not a consecutive-day chain. Each time the outer ring fills, the streak count goes up by 1 — so two goal completions in a single day are now +2. The outer ring resets and starts filling again after each completion, so a long day visibly racks up multiple streaks. The kill rule is unchanged: an active day with zero completions resets the count to 0; paused days (no records) preserve it.
   - Visible celebration: filling the outer ring now bursts confetti from the centre of the disk, with the ring latched at 100% for the moment of the burst. Closes the loop that "the ring fills and nothing happens"; the count's match with the visual is now obvious.
   - Pauses are now recorded as part of each cycle's history: screen-lock auto-pauses, manual pauses, and app-shutdown spans (graceful or not). Cycle stats still exclude pause time as they did before — this is purely additional metadata, useful when a cycle's real-time span doesn't match its planned duration.
   - Internal: 5-second state heartbeat on every tick (AppLastAliveAt), and an AppDomain.ProcessExit safety net for ungraceful exits (crashes, Environment.Exit, OS shutdown). Worst case after an abrupt exit is now ~5 s of lost cycle progress, with the gap recorded as an AppShutdown pause on the cycle.
   - Internal: AppState's JSON serializer now emits enums as strings ("ScreenLock", "ManualPause", "AppShutdown") rather than integers, for readability and stability against enum reorderings.

v.1.1.0
   - New: configurable day-rollover time. Set when your day starts (default 06:00) in Settings; when the clock crosses the boundary — or the app resumes from a lock that straddled it — the cycle resets to your chosen start mode (Seated by default) and a "New day" toast appears.
   - All day-based stats now honor your rollover time instead of calendar midnight: today's ring, streak, heatmap, cycles-per-day chart, and the daily achievement counters all use it. A 02:30 standing cycle with a 06:00 rollover now counts toward the day you mentally finished, not the next one. The rollover itself never breaks your streak — even if it caught a cycle mid-flight.
   - New: "Always on top" toggle in Settings (default on). Also fixes the Dashboard window sometimes ending up behind the main disk on macOS.
   - First launch now drops straight into the Settings tab, with "Start with Windows" / "Start at login" pinned at the top tagged Recommended — replaces the old yes/no popup so configuration is visible, not buried.
   - New clock-face time picker for the rollover setting: two concentric rings (hours outer, minutes inner), drag / scroll / arrow keys to set, or click the central HH:MM and type the time directly.
   - Internal: streak / achievement / heatmap math is now parameterised on the rollover time, with TimeSpan.Zero as the calendar-day degenerate case. New CycleOutcome.RolloverReset distinguishes app-initiated resets from user resets.

v.1.0.3

   - Internal: substantial cleanup pass — dead code removed, error handling tightened to typed catches, lock consistency restored across HistoryStore reads, app-state persistence moved out of Features/Shell to Core/State to dissolve a 7-file import cycle, and macOS bundle id renamed for identity consistency.

v.1.0.2
   - Background update checks now run on every sit/stand cycle start (throttled to at most once per 30 minutes), so long-running sessions pick up new releases without restarting the app.
   - The daily goal is now a number of completed standing cycles rather than a number of standing minutes. The settings field reads "Daily standing cycles"; the outer ring and Today stat show cycle progress (with the minutes-stood-today shown as a secondary number). A cycle only counts if it ran to natural completion — bailing out via Swap doesn't count toward the goal, though the time you did spend standing is still tracked.
   - Streak follows the new cycle goal: a streak day is an active day that hit the cycle count. Days where the screen was locked all day or the app was paused are "paused" — neither hit nor miss. No mid-day instant-loss action; the streak fails at end-of-day if an active day finishes below the goal.
   - Old saved settings using the previous minutes-based goal are ignored; the new daily-cycle goal starts at its default. Lifetime achievements remain minutes-honest.
   - Stats tab: the 13-week minutes heatmap is now half-width, balanced by a new 14-day cycles-per-day bar chart on the right. The main-disk dashboard button switched from a cog to a stats glyph so the contents are less hidden.
